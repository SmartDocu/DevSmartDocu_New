⚠ 가장 시급한 4곳 — 백엔드를 완전히 우회하는 유일한 경로

gendocs_realtimes, genchapters_realtimes, notifications, notification_users — 이 4개는 프론트가 FastAPI를 거치지 않고 Supabase Realtime을 anon key + 사용자 JWT로 직접 구독합니다(frontend/src/hooks/useJobNotifications.js, useNotifications.js 등). 이번 세션 내내 다뤘던 백엔드 소유권 검증은 이 4개 테이블엔 전혀 적용되지 않습니다 — RLS가 없으면 filter 파라미터를 클라이언트가 조작해 다른 사용자의 알림/생성 상태를 그대로 구독할 수 있습니다.

같은 이유로 chat_sessions/chat_qas/chat_favorites도 우선순위가 높습니다 — d2chat/history/supabase_storage.py 코드 주석에 "라우터가 토큰으로 생성한 클라이언트(sb)를 받는다 (RLS 적용)"라고 명시돼 있어, 애초에 RLS가 켜져 있다는 전제로 설계된 테이블입니다.

참고 — "결정 필요"의 상당수는 현재 service-role 전용이라 RLS를 걸어도 이 앱 자체의 접근 경로는 안 바뀝니다. 그래도 방어심층(키 유출, Supabase 대시보드 직접 접근, 향후 프론트 직접 접근 추가 등)을 위해 걸지 결정이 필요하다는 뜻으로 분류했습니다. "미사용으로 보임"이라고 적힌 항목은 코드 정적분석 기준이라 실제로는 쓰이고 있을 수 있습니다(이번 조사에서도 d2shared 경유 테이블 몇 개를 이렇게 놓쳤다가 다시 잡아냈습니다) — 결정 전에 한 번 더 확인을 권합니다. 삭제예정_/임시_ 접두사 테이블 24개와 RPC 함수는 이미 정리 대상으로 분류돼 있어 제외했습니다.
